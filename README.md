# Comandos Deploy Hub

Здесь мы собираем и обновляем типовые шаблоны деплоя для разных сервисов.  

## 🚀 Быстрый старт (WordPress Engine)
Чтобы развернуть WordPress со всеми премиум-оптимизациями (PageSpeed 98+), просто запустите:
```bash
curl -sSL https://raw.githubusercontent.com/Comandosai/comandos-deploy-hub/main/wp-stack/setup.sh | bash
```
## Что внутри
- Папки шаблонов (каждый шаблон — отдельный каталог с описанием).
- Унифицированные правила упаковки и структуры.

## Правила для шаблонов
- Одна папка на сервис/шаблон.
- Внутри: `README.md`, `setup.sh`, `docker-compose.yml.j2`.
- Пакет должен быть легким (без `node_modules`, без `.git`).

## Модульный стандарт (обязательно для новых стеков)
Цель: любой стек должен ставиться в любом порядке относительно других стеков и корректно с ними взаимодействовать.

### 1) Независимость от порядка установки
- Скрипт должен поддерживать сценарий `install -> install` в любом порядке (например, сначала WordPress, потом n8n, и наоборот).
- Повторный запуск `setup.sh` не должен ломать текущую инфраструктуру.
- Обновление и переустановка должны быть разными режимами (без случайного удаления данных).

### 2) Единая внешняя сеть
- Все сервисы, которым нужно взаимодействие между стеками, подключаются к общей external-сети: `comandos-network`.
- Скрипт обязан проверять сеть и создавать её при отсутствии:
  - `docker network inspect comandos-network || docker network create comandos-network`
- Внутренние БД/кэши держать в internal-сетях, если к ним не нужен межстековый доступ.

### 3) Traefik-совместимость
- Не требовать “своего” Traefik как единственного варианта.
- Сначала пытаться подключиться к уже работающему Traefik, а не поднимать второй.
- Определять `certResolver` и динамическую папку автоматически, с безопасным fallback.
- Роутеры и сервисы должны иметь уникальные имена (без конфликтов между стеками).

### 4) Идемпотентность и безопасность
- Все `setup.sh` писать в режиме строгой ошибки: `set -euo pipefail`.
- Любые “разрушающие” действия (drop volume/db, reset) только через явный режим/флаг и подтверждение.
- Не использовать `latest` без осознанной причины для критичных компонентов (или фиксировать тег в `.env`).

### 5) Межсервисные интеграции по DNS в сети Docker
- Для связи стеков использовать DNS-имена контейнеров/сервисов в `comandos-network`.
- Не хардкодить localhost/127.0.0.1 для межконтейнерного трафика.
- Минимальный smoke-check после деплоя: сервис доступен внутри сети и через Traefik.

### 6) Стандарты интерфейса setup.sh
- Единые базовые команды:
  - `./setup.sh` — установка/обновление
  - `./setup.sh --stop` — остановка
  - `./setup.sh --logs` — логи
- В конце установки печатать:
  - URL сервиса
  - путь данных
  - краткий статус интеграции с Traefik/сетью

### 7) Обязательный чеклист перед коммитом нового стека
- [ ] Стек запускается на чистом сервере.
- [ ] Стек запускается, если уже есть другой стек и Traefik.
- [ ] Повторный `setup.sh` проходит без поломок.
- [ ] Сервис доступен по HTTPS-домену через Traefik.
- [ ] Межстековая связь в `comandos-network` работает.
