# Подключение отдела продаж

Этот навык нужен для подключения уже существующей клиентской инфраструктуры.

Что делает:
- находит `Supabase`;
- находит `n8n`;
- загружает workflow отдела продаж;
- загружает отдельный тестовый workflow для проверки базы;
- создает и привязывает соединения `Supabase`, `Postgres`, `MCP`;
- при необходимости создает соединения `OpenRouter`, `OpenAI`, `Telegram`;
- выполняет первичную проверку работоспособности.

## Когда использовать

Используйте этот навык, когда:
- база знаний уже загружена;
- у клиента уже есть или почти готова инфраструктура;
- нужно быстро связать `Supabase`, `n8n`, workflow и `MCP`.

## Что потребуется

Обязательно:
- доступ к `Supabase` или к серверу, где он стоит;
- доступ к `n8n` или к серверу, где он стоит;
- `x-license-key` для кастомного `MCP`.

Опционально:
- `OpenRouter API key`;
- `OpenAI API key`;
- `Telegram bot token`.

## Важно про `MCP`

Для кастомного `MCP` поле `x-license-key` обязательно.

Если пользователь не дал `x-license-key`, навык должен остановиться на настройке `MCP` и запросить этот ключ.

## Команда 1. Скачать и установить навык

Скопируйте и вставьте агенту:

```text
Скачай и установи навык `Подключение отдела продаж` из репозитория `https://github.com/Comandosai/comandos-deploy-hub`, директория `skills/podklyuchenie-otdela-prodazh`.

Адаптируй установку под текущего агента:
- если это Codex, положи файлы в codex-совместимую skill-структуру;
- если это Claude, положи файлы в claude-совместимую структуру;
- если это Antigravity, положи файлы в antigravity-совместимую структуру.

Установи:
- bundle entrypoint;
- references;
- workflow map;
- все файлы навыка для подключения `Supabase`, `n8n`, `MCP` и тестового агента.

После установки ничего не запускай автоматически.
Просто покажи, что навык установлен, и скажи, какой следующей командой запускать подключение инфраструктуры.
```

## Команда 2. Найти `Supabase` и `n8n`

Скопируйте и вставьте агенту:

```text
Используй навык `Подключение отдела продаж`.

Сначала проверь инфраструктуру клиента:
- найди `Supabase`;
- найди `n8n`;
- определи, находятся ли они на одном сервере или на разных;
- если что-то не найдено автоматически, запроси у меня только недостающие доступы.

Также проверь:
- используется ли стандартная схема `public` или другая;
- есть ли уже созданные соединения;
- есть ли уже загруженные workflow.

После этого коротко покажи, что ты нашел.
```

## Команда 3. Подключить `Supabase` и создать соединения

Скопируйте и вставьте агенту:

```text
Теперь настрой соединения для базы.

Нужно:
- создать или обновить соединение `Supabase`;
- создать или обновить соединение `Postgres`;
- создать или обновить соединение `MCP Postgres`.

Для `MCP Postgres` используй:
- credential type: `HTTP Multiple Headers Auth`
- endpoint: `https://postgres.mcp.comandos.ai`

Headers:
- `db_host`
- `db_port`
- `db_name`
- `db_user`
- `db_password`
- `db_schema`
- `x-license-key`

Если каких-то параметров не хватает, запроси у меня только недостающее.
Если схема не указана, спроси, используется ли `public`.
```

## Команда 4. Загрузить workflow

Скопируйте и вставьте агенту:

```text
Теперь загрузи workflow отдела продаж в `n8n`.

Нужно загрузить:
- прием входящих сообщений;
- главный оркестратор;
- квалификацию;
- консультацию;
- передачу человеку;
- тестовый workflow;
- уведомления об ошибках;
- отдельный workflow `Проверка базы знаний`.

Не плодить дубликаты, если эти workflow уже есть.
После загрузки покажи, какие workflow были импортированы или обновлены.
```

## Команда 5. Привязать соединения к workflow

Скопируйте и вставьте агенту:

```text
Теперь привяжи созданные соединения ко всем нужным узлам workflow.

Нужно:
- подставить `Supabase`;
- подставить `Postgres`;
- подставить `MCP`;
- если даны ключи, подставить `OpenRouter`, `OpenAI`, `Telegram`;
- не использовать битые или пустые credentials;
- проверить, что у workflow не осталось незаполненных соединений.

После завершения покажи, что было привязано.
```

## Команда 6. Настроить тестового агента

Скопируйте и вставьте агенту:

```text
Настрой отдельный workflow `Проверка базы знаний`.

Он должен:
- использовать общий тестовый prompt;
- работать через `MCP`;
- использовать `knowledge_rag` как основной источник;
- использовать `products_live` для точных товарных данных;
- не выдумывать ответы;
- прямо говорить, если данных в базе не хватает.
```

## Команда 7. Финальная проверка

Скопируйте и вставьте агенту:

```text
Проверь итоговую работоспособность.

Нужно проверить:
- доступ к `Supabase`;
- доступ к `Postgres`;
- доступ к `MCP`;
- наличие `x-license-key`;
- загрузку workflow;
- отсутствие пустых соединений;
- хотя бы один тестовый запуск.

После этого дай краткий итоговый отчет:
- что найдено;
- что подключено;
- какие workflow загружены;
- что осталось сделать вручную, если осталось.
```
