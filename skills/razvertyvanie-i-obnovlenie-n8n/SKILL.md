# Развертывание и обновление n8n

Это отдельный навык для работы именно с `n8n-stack-v2`.

Он должен:
- сначала проверить, есть ли в корне проекта файл `DANNYE_DLYA_RAZVERTYVANIYA.md`;
- если файл есть, читать данные оттуда;
- если файла нет, запросить недостающие данные или предложить создать шаблон;
- получить доступ к серверу;
- проверить, есть ли уже установленный `n8n`;
- если `n8n` есть, спросить, нужно ли обновление;
- если `n8n` нет, поставить новый;
- запросить домен, почту для SSL и пароль администратора, если их не удалось определить автоматически;
- запросить `x-license-key`, если он нужен для кастомных узлов и дальнейшей связки с `MCP`;
- запустить установочный сценарий и выдать отчет.

## Правила

- Все названия и пояснения держать по-русски.
- Не спрашивать пользователя о том, что можно определить на сервере автоматически.
- Если в корне проекта есть `DANNYE_DLYA_RAZVERTYVANIYA.md`, сначала читать его и брать данные оттуда.
- Если `n8n` уже найден, до обновления обязательно спросить подтверждение.
- Использовать `n8n-stack-v2` как единственный стандартный путь установки и обновления.
- Деплойный путь считать фиксированным: `/root/n8n`.
- Если нужен `x-license-key` для кастомных узлов или дальнейшей настройки `MCP`, обязательно запросить его.
- Использовать интерактивную SSH-сессию как основной режим для длинных операций по установке, docker и проверкам.
- После установки или обновления выполнять preflight по custom node packages и credential types, а не считать стек готовым только по поднятым контейнерам.
- После каждого этапа самостоятельно предлагать следующий шаг в одном готовом копируемом `text`-блоке.
- Если следующий шаг уже не нужен, потому что он выполнен, пропускать его и предлагать следующий релевантный этап.
- Не перекладывать на пользователя навигацию по сценарию.

## Обязательные проверки после установки или обновления

- проверить, что контейнеры действительно поднялись;
- определить `project_id`;
- проверить наличие обязательных custom node packages;
- если нужного пакета нет, докачать его сразу;
- отдельно проверить:
  - `@comandosai/n8n-nodes-amo-crm`;
  - `@comandosai/n8n-nodes-doc-extract`;
  - provider для `comandosLsiKeysApi`.

Если этих пакетов или credential types нет, навык не должен говорить, что `n8n` полностью готов к работе отдела продаж.

## Что должно быть на выходе

- новый или обновленный `n8n`;
- рабочий домен;
- рабочий SSL;
- сохраненные настройки стека;
- проверенные или докачанные обязательные packages;
- проверенные credential types для кастомных узлов;
- отчет о том, что найдено, что обновлено и что осталось сделать дальше.
- В конце выдан один конкретный следующий шаг для продолжения общего сценария: векторизация базы или подключение отдела продаж, в зависимости от текущего состояния.
