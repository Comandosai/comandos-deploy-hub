# Развертывание и обновление n8n

Полный пакет для установки или обновления `n8n` через `n8n-stack-v2`.

Что делает:
- получает доступ к серверу;
- проверяет, есть ли уже установленный `n8n`;
- если `n8n` уже есть, уточняет, нужно ли обновление;
- если `n8n` нет, ставит новый экземпляр;
- спрашивает домен, почту для SSL и пароль администратора только если это не найдено автоматически;
- запускает `n8n-stack-v2`;
- перед обновлением делает backup текущего стека;
- при обновлении сохраняет `workflow`, `credentials`, `variables`, `project sharing`, `tags` и пользовательские настройки;
- после установки делает preflight по пакетам и credential types;
- выдает краткий итоговый отчет.
- после каждого этапа сам предлагает следующий шаг и выдает готовый копируемый блок команды.

## Когда использовать

Использовать, когда нужно:
- поднять новый `n8n`;
- обновить существующий `n8n`;
- привести стек клиента к стандартному состоянию через `n8n-stack-v2`.

Если файла нет:

## Что потребуется

Обязательно:
- доступ к серверу;
- домен для `n8n`;
- почта для SSL;
- пароль администратора `n8n`.

Опционально:
- `x-license-key`, если пользователь сразу хочет готовить почву под кастомные узлы и `MCP`.

## Что надо проверять по умолчанию

После установки или обновления навык должен проверить и при необходимости докачать:
- `@comandosai/n8n-nodes-amo-crm`;
- `@comandosai/n8n-nodes-doc-extract`;
- provider для `comandosLsiKeysApi`.
- при обновлении он также обязан проверить, что все прежние `workflow` и `credentials` остались на месте и не потеряли project-sharing.

Иначе `n8n` может быть формально поднят, но не готов к workflow отдела продаж.

## Команда 4. Установить или обновить `n8n`

```text
Теперь запусти `n8n-stack-v2` как основной установочный и обновляющий путь.

Если `n8n` не установлен:
- поставь новый экземпляр.

Если `n8n` уже установлен и я подтвердил обновление:
- аккуратно обнови существующий экземпляр;
- сначала сделай backup текущей базы, volume, `.env` и deploy-файлов;
- по возможности сохрани текущие настройки;
- сохрани все существующие `workflow`, `credentials`, `variables`, `users`, `tags` и project bindings;
- после обновления проверь, что в новой версии `n8n` они видны и работают;
- используй фиксированный путь `/root/n8n`.

После завершения покажи:
- что было сделано;
- на каком домене поднят `n8n`;
- что SSL настроен;
- рабочий ли контейнер;
- сохранены ли все workflow и credentials.
```

```text
- что готово для следующего шага.
```
