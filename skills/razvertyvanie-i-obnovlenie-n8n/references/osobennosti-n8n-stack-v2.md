# Особенности n8n-stack-v2

Источник:
- `/Users/artemlahtin/Documents/comandos-deploy-hub/n8n-stack-v2`

Ключевые правила:
- стандартный путь деплоя: `/root/n8n`
- использовать только `n8n-stack-v2`
- поддерживается новая установка и обновление
- стек сам работает с `PostgreSQL`, `Redis`, `worker`, `Traefik`
- после установки возможна автоподготовка базовых credentials
- встроенный `Traefik` должен работать в одном согласованном режиме, без конфликта `file provider` и `docker labels`
- `n8n` за прокси должен запускаться с корректной proxy-настройкой, включая `N8N_PROXY_HOPS=1` для одного proxy-hop
- пароль роли `n8n` в `Postgres` не должен расходиться с `.env` после обновления
- после деплоя обязателен smoke-test после рестарта

Что важно учитывать в навыке:
- если найден старый `n8n`, нужно подтвердить обновление;
- если установка уже была, не ломать текущие данные;
- нужно уважать фиксированный путь `/root/n8n`.
- если обновление прошло, в новой версии должны остаться те же `workflow`, `credentials`, `project sharing` и пользовательский стейт.
