# Векторизация и загрузка базы

Этот навык нужен для подготовки базы знаний и товарной таблицы клиента.

Что делает:
- берет сырые документы как есть;
- приводит папку в рабочую структуру;
- создает `__workspace`;
- собирает `docs`, `product_memory` и `products_live`, если есть factual product rows;
- отправляет документы в runtime API;
- получает чанки и embeddings;
- записывает знания в `knowledge_rag`;
- записывает товарные строки в `products_live`.

## Когда использовать

Используйте этот навык, когда:
- у клиента есть папка с документами;
- нужно быстро подготовить знания и товары для дальнейшей работы;
- нужно загрузить результат в `Supabase`.

## Что потребуется

- папка с исходными документами;
- доступ к `Supabase` или к серверу, где он стоит;
- лицензионный ключ `COMANDOS`;
- хост, с которого можно достучаться до `api.comandos.ai`.

## Команда 1. Навести обычную структуру документов

Скопируйте и вставьте агенту:

```text
Возьми все файлы из текущей рабочей папки как есть, без предварительной ручной подготовки.
Сначала наведи обычную понятную структуру документов:
- разложи хаотичные файлы по логическим группам;
- отдели основные документы, продуктовые материалы, отзывы, инструкции и таблицы;
- не используй пока COMANDOS bundle и специальные skills;
- не векторизуй ничего на этом шаге;
- просто подготовь чистую рабочую структуру, с которой будет удобно работать дальше.

После завершения покажи:
- какие папки ты создал;
- какие файлы куда разложил;
- где теперь лежит основная папка с документами для следующего шага.
```

## Команда 2. Разобрать документы и собрать `__workspace`

Скопируйте и вставьте агенту:

```text
Используй навык `Векторизация и загрузка базы`.

Возьми документы из папки `/путь/к/моим/документам`.
Создай `__workspace`.
Сделай:
- `docs`
- `product_memory`, если нужно
- `products_live`, если есть реальные factual live rows

Важно:
- не делай `registry_rows`;
- не придумывай отдельную самодельную таблицу;
- если factual live rows есть, сразу создай canonical `products_live`;
- `tenant_id` в `products_live` по умолчанию ставь `global`, если я отдельно не указал другой.

После завершения покажи:
- какие файлы созданы в `docs`;
- создана ли `products_live`;
- если не создана, коротко объясни почему.
```

## Команда 3. Подготовить `Supabase`

Если `Supabase` еще не развернут:

```text
Теперь подготовь инфраструктуру для ingestion.

Я дам доступ к серверу клиента.
Подключись к серверу, проверь, есть ли уже развернутый Supabase.

Если Supabase нет:
- разверни его;
- примени `CYBEROP_BOOTSTRAP_SCHEMA.sql`;
- создай и заполни нужный `.env` для runner;
- сохрани параметры подключения для дальнейшей записи данных.

Если для этого нужны логин, пароль, IP или SSH-ключ, запроси у меня только недостающие доступы.
Ничего лишнего не спрашивай.

После завершения коротко покажи:
- развернут ли Supabase;
- применена ли схема;
- готов ли runner к записи в базу.
```

Если `Supabase` уже есть:

```text
Supabase уже развернут.
Подключись к нему, проверь доступ, проверь наличие нужных таблиц и подготовь `.env` для runner.

Если не хватает параметров подключения, запроси у меня только:
- host
- port
- db name
- user
- password
- ssl, если нужен

После завершения скажи, что подключение к Supabase готово.
```

## Команда 4. Запустить ingestion

Скопируйте и вставьте агенту:

```text
Используй `vector-ingestion-launcher`.
Возьми prepared-документы из созданного `__workspace`.
Запусти ingestion flow:
- отправь документы в `commandos-api`;
- получи chunks и embeddings;
- загрузи результат в Supabase.

Если execution-host не может достучаться до `api.comandos.ai`, используй hybrid mode:
- получи JSON с chunks и embeddings на машине с интернетом;
- затем импортируй этот JSON в Supabase.

После завершения покажи:
- сколько документов отправлено;
- сколько чанков получено;
- сколько записей записано в `knowledge_rag`;
- сколько записей записано в `products_live`;
- были ли ошибки.
```

## Команда 5. Проверить результат

Скопируйте и вставьте агенту:

```text
Проверь результат в Supabase и коротко отчитайся:
- сколько строк в `knowledge_rag`;
- сколько строк в `products_live`;
- есть ли пустые или битые записи;
- есть ли ошибки, которые надо исправить перед следующим прогоном.
```
