# Порядок работы

## Шаг 1. Взять сырые документы

Пользователь просто складывает все материалы в одну папку:
- документы компании;
- продуктовые материалы;
- FAQ;
- отзывы;
- инструкции;
- таблицы, если они есть.

Не нужно заранее наводить порядок руками.

## Шаг 2. Привести папку в обычную структуру

Сначала агент приводит хаотичную папку в понятную рабочую структуру.
Это делается без векторизации.

## Шаг 3. Создать `__workspace`

После этого запускается `doc-splitter`, который должен:
- создать `docs`;
- создать `product_memory`, если нужно;
- создать `products_live`, если есть factual live rows.

## Шаг 4. Подготовить `Supabase`

Если `Supabase` уже есть:
- использовать готовые доступы.

Если `Supabase` нет:
- развернуть его;
- накатить схему;
- подготовить окружение для runner.

## Шаг 5. Запустить ingestion

Дальше runner:
- отправляет docs в runtime API;
- получает chunks и embeddings;
- отправляет knowledge chunks в `knowledge_rag`;
- отправляет `products_live` rows в `products_live`.

## Шаг 6. Проверить результат

В конце нужно проверить:
- сколько строк в `knowledge_rag`;
- сколько строк в `products_live`;
- не было ли ошибок.
