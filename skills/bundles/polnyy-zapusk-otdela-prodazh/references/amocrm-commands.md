# Команды для этапа AmoCRM

## Команда 13. Снять структуру AmoCRM

```text
Используй навык `Полный запуск отдела продаж`.

Перейди к этапу `Снятие структуры AmoCRM`.

Сначала проверь:
- что базовый отдел продаж уже развернут;
- что Telegram-тестирование отдела продаж уже проходило;
- что есть доступ к `MCP AmoCRM`;
- что есть `x-license-key` или другой ключ, через который MCP AmoCRM понимает клиента;
- что в `DANNYE_DLYA_RAZVERTYVANIYA.md` есть данные проекта.

Не трать время на поиск способа подключения.
Если `MCP AmoCRM` уже есть в `n8n`, используй сразу фиксированный маршрут:
- узел: `MCP Client Tool` или текущий `MCP`-узел пакета;
- endpoint: `https://amocrm.mcp.comandos.ai`;
- transport: `HTTP Streamable`;
- authentication: `Multiple Headers Auth`;
- credential: `MCP AmoCRM`;
- header: `x-license-key`.

Сначала сделай минимальный проверочный вызов через этот узел.
Если первый ответ не получен:
- не придумывай другой URL;
- не уходи в `SSH`;
- не лезь в контейнер `MCP`;
- сначала исправь credential, project binding или сам вызов из `n8n`.

Только после успешного первого ответа переходи к снятию полной структуры.

Через MCP AmoCRM получи:
- список воронок;
- список стадий по выбранной основной воронке;
- список полей контакта;
- список полей сделки, если доступно;
- список доступных действий MCP AmoCRM.

После получения данных:
- покажи найденные воронки;
- предложи основную воронку;
- покажи стадии с `id`;
- покажи поля контакта с `id` и типами;
- покажи поля сделки с `id` и типами, если доступны;
- явно скажи, если поля сделки текущим MCP не снимаются.

Запиши в `DANNYE_DLYA_RAZVERTYVANIYA.md`:
- выбранную воронку;
- `pipeline_id`;
- стадии с `id`;
- поля контакта с `id` и типами;
- поля сделки с `id` и типами, если доступны;
- доступные действия MCP AmoCRM.

Обнови `KONTEXT_VNEDRENIYA_OTDELA_PRODAZH.md`.

После завершения предложи следующий шаг: `Сборка CRM-карты AmoCRM`.
```

## Команда 14. Собрать CRM-карту AmoCRM

```text
Используй навык `Полный запуск отдела продаж`.

Перейди к этапу `Сборка CRM-карты AmoCRM`.

Используй уже снятую структуру AmoCRM из `DANNYE_DLYA_RAZVERTYVANIYA.md`.

Сначала покажи пользователю:
- выбранную воронку;
- стадии;
- поля контакта;
- поля сделки, если есть;
- текущие предварительные правила.

Попроси пользователя подтвердить или поправить:
- что означает каждая стадия;
- когда переводить сделку на каждую стадию;
- какие поля заполнять всегда;
- какие поля заполнять только если клиент явно сказал;
- какие поля заполнять только при handoff;
- что делать, если данных не хватает.

После согласования собери карту:
- `field_map`: что писать в какое поле;
- `stage_map`: когда ставить какой этап;
- `allowed_crm_actions`;
- `forbidden_crm_actions`;
- `handoff_crm_rules`;
- `test_cleanup_rules`.

Сохрани карту в:
- `Prompts/amocrm_crm_map.json`
- `AmoCRM_skill/WORKLOG.md`
- `DANNYE_DLYA_RAZVERTYVANIYA.md`

Обнови `KONTEXT_VNEDRENIYA_OTDELA_PRODAZH.md`.

После завершения предложи следующий шаг: `Сборка AmoCRM-промптов и workflow`.
```

## Команда 15. Собрать AmoCRM-промпты и workflow

```text
Используй навык `Полный запуск отдела продаж`.

Перейди к этапу `Сборка AmoCRM-промптов и workflow`.

Используй:
- `Prompts/amocrm_crm_map.json`;
- `DANNYE_DLYA_RAZVERTYVANIYA.md`;
- `KONTEXT_VNEDRENIYA_OTDELA_PRODAZH.md`;
- текущие промпты квалификатора и консультанта;
- текущий workflow `02_Main_Orcestrator`;
- workflow `05_WF_Human_Handoff_Workflow`;
- шаблон или текущую версию `07_WF_CRM_Operator`.

Собери или обнови:
- `Prompts/prompt_qualifier.md`;
- `Prompts/prompt_consultant.md`;
- prompt AI-узла `CRM Operator` в `07_WF_CRM_Operator`.

После сборки сразу вставь эти три prompt-а в живой `n8n`:
- квалификатор -> `03_WF_Qualification`;
- консультант -> `04_WF_Consultation`;
- CRM Operator -> `07_WF_CRM_Operator`.

Не создавай и не обновляй `Prompts/prompt_orchestrator_crm_operator.md`.
Не переписывай prompt оркестратора.
Поле `reply_to_user` в оркестраторе оставь как есть.
Handoff prompt меняй только по отдельной явной команде пользователя.

Правила:
- оркестратор не должен напрямую использовать `MCP AmoCRM`;
- оркестратор только проверяется: он должен вызывать `crm_operator`;
- `crm_operator` должен работать с полями и стадиями;
- квалификатор и консультант не работают с AmoCRM напрямую;
- source of truth для карты AmoCRM — `Prompts/amocrm_crm_map.json` и `DANNYE_DLYA_RAZVERTYVANIYA.md`.

Проверь в n8n:
- workflow `07_WF_CRM_Operator` существует;
- workflow `02_Main_Orcestrator` имеет tool `crm_operator`;
- `MCP AmoCRM` не подключен напрямую к оркестратору;
- prompt оркестратора не был изменен;
- `crm_operator` возвращает нормальный JSON, а не строку внутри `output`;
- результат `crm_operator` пишется в `public.lead_events.payload`.

После завершения:
- покажи, какие workflow изменены;
- покажи, какие prompt-ы обновлены;
- обнови контекст проекта;
- предложи следующий шаг: `AmoCRM sales-тест`.
```

## Команда 16. AmoCRM sales-тест

```text
Используй навык `Полный запуск отдела продаж`.

Перейди к этапу `AmoCRM sales-тест`.

Перед тестом:
- проверь, что `07_WF_CRM_Operator` активен или опубликован;
- проверь, что оркестратор вызывает `crm_operator`;
- проверь, что `MCP AmoCRM` не подключен напрямую к оркестратору;
- попроси пользователя удалить тестовые сделки/контакты в AmoCRM, если нужен полностью чистый визуальный прогон;
- очисти рабочие таблицы Supabase;
- не трогай `knowledge_rag` и `products_live`.

Запусти живой sales-тест.

Жесткое правило теста:
- тест всегда вести как живой многошаговый диалог;
- делать не меньше 5 и не больше 8 сообщений от лица клиента;
- вопросы строить по материалам компании, `brief`, базе знаний, каталогу, условиям покупки, срокам, возражениям и handoff-ситуациям;
- в каждом новом прогоне придумывать новый набор вопросов;
- не гонять один и тот же шаблон разговора;
- имитировать разные типы клиентов: осторожный, спешащий, сомневающийся, уже готовый купить, сравнивающий варианты;
- цель теста не просто дойти до конца, а найти слабые места в ответах, маршрутизации и записи в CRM.

Проверь:
- квалификацию;
- консультацию;
- handoff;
- вызов `crm_operator`;
- запись `crm_sync` в `lead_events`;
- заполнение полей AmoCRM;
- движение сделки по правильному этапу;
- создание заметки и задачи при handoff;
- отсутствие прямых вызовов `MCP AmoCRM` из оркестратора.

Сохрани:
- raw dialog report;
- normalized summary report.

В summary отдельно покажи:
- какие именно 5-8 сообщений использовались в этом прогоне;
- почему был выбран именно такой сценарий разговора;
- что технически работает;
- какие поля заполнились;
- какой этап сделки поставлен;
- где агент ошибся в диалоге;
- что нужно поправить в трех промптах: квалификатор, консультант, CRM Operator;
- отдельно покажи, если проблема не в prompt-е, а в связи workflow.

Обнови `KONTEXT_VNEDRENIYA_OTDELA_PRODAZH.md`.

Предложи только один следующий шаг: `Точечная правка prompt-ов по итогам AmoCRM-теста`.
```
