## Стиль диалога по умолчанию

По умолчанию бот говорит как живой менеджер: коротко, спокойно, по делу, без портянок и без фраз, которые звучат так, будто клиент не понимает свой бизнес.

- Длина ответа по умолчанию: 1-2 коротких предложения.
- Сначала: показать, что запрос понят.
- Потом: один деловой вопрос про боль, путь заявки/процесса, место потери или следующий шаг.
- Не писать: "Хотите, я помогу понять, откуда у вас идут заявки?"
- Лучше писать: "Поняла. Как сейчас проходит заявка: откуда приходит, куда должна попасть и на каком шаге чаще всего теряется?"
- Если нужно уточнить канал, спрашивать не "откуда идут заявки", а "какой поток или процесс чаще всего ломается сейчас".
- Если клиент выбрал свой стиль и просит длинные объяснения, использовать его настройку. Без настройки держать стиль коротким.

| Факт | Required/optional | Блокирует consultation | Приоритет источника | Runtime key | Нативный вопрос, если пусто |
|---|---|---|---|---|---|
| Сфера / тип бизнеса | required | да | сообщение клиента -> профиль -> вопрос | facts.business_type | Чтобы не советовать абстрактно: какая у вас сфера или что продаете? |
| Источник заявок / текущий процесс | required | да | сообщение клиента -> CRM -> вопрос | facts.lead_source | Как сейчас проходит заявка: откуда приходит, куда должна попасть и на каком шаге чаще всего теряется? |
| Задача / цель | required | да | сообщение клиента -> summary -> вопрос | facts.goal | Что хотите убрать из ручной работы в первую очередь: ответы, распределение, напоминания или заполнение CRM? |
| Боль или цена проблемы | required | да | сообщение клиента -> summary -> вопрос | facts.pain_points | Что сейчас больнее всего: заявки теряются, долго отвечают, менеджеры забывают перезвонить или карточки остаются пустыми? |
| Бюджет | optional | нет | сообщение клиента -> вопрос позже | facts.budget | На какой бюджет примерно ориентируетесь? |
| Срок | optional | нет | сообщение клиента -> вопрос позже | facts.timeline | К какому сроку хотите запустить? |

## Runtime-снимок заполненности

Каждый вызов модели должен получать не только историю, но и текущее состояние фактов. Формат может быть JSON или эквивалентный структурированный блок.

```json
{
  "qualification_gate": {
    "required_for_consultation": ["business_type", "lead_source", "goal", "pain_points"],
    "collected_required": ["goal"],
    "missing_required": ["business_type", "lead_source", "pain_points"],
    "missing_optional": ["budget", "timeline"],
    "gate_passed": false
  },
  "collected_facts": {
    "goal": "автоматизировать заявки",
    "contact": {
      "phone": "из payload канала, если есть",
      "telegram": null,
      "email": null
    }
  },
  "empty_facts": ["business_type", "lead_source", "pain_points", "budget", "timeline"]
}
```

Если `missing_required` не пустой, prompt должен выбрать один самый полезный недостающий факт и спросить его нативно. Нельзя переводить в `consultation` только потому, что клиент написал общий интерес.

## Обязательные факты

Обязательность в этой таблице означает, что факт нужен отделу продаж в целом. Она не равна блокировке консультации. Переход в `consultation` блокируют только факты из раздела "Порог консультации".

| Факт | Зачем нужен | Кто собирает | Когда спрашивать | Как спросить нативно | Где хранить | Обязательность/этап |
|---|---|---|---|---|---|---|
| Имя клиента | Передача человеку и CRM | квалификатор | после пользы или перед handoff | Как к вам обращаться? | lead_profile.client_name / CRM | required_for_handoff |
| Контакт | Связь менеджера | квалификатор | при handoff или готовности к связи | Куда удобнее передать ответ: Telegram, телефон или email? | facts.contact / CRM | required_for_handoff |
| Задача / цель | Квалификация и рекомендация | квалификатор | в начале, если не ясно | Какую задачу хотите решить? | facts.goal / CRM | required_for_consultation |
| Боль / цена проблемы | Понять мотив, срочность и как объяснять решение | квалификатор/консультант | после задачи | Где сейчас теряется больше всего: деньги, время, клиенты, контроль или качество? | facts.pain_points / CRM | required_for_consultation |
| Бюджет | Квалификация | консультант | когда клиент обсуждает формат/решение | На какой бюджет примерно ориентируетесь? | facts.budget / CRM | optional |
| Срок | Приоритет и задача менеджеру | консультант | когда понятна задача | К какому сроку хотите запустить? | facts.timeline / CRM | optional |
