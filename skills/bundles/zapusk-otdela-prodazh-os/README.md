# Запуск отдела продаж ОС

Новый пакет запуска отдела продаж в COMANDOS ОС.

Он нужен для сценария, где клиент ничего не разворачивает у себя: отдел продаж живет в COMANDOS Hub, а клиент подключает свои Telegram, Supabase, amoCRM, базу знаний и prompts.

## Установка

```bash
export COMANDOS_LICENSE_KEY="ВСТАВИТЬ_КЛЮЧ_ЛОКАЛЬНО"

curl -fsSL \
  -H "Authorization: Bearer $COMANDOS_LICENSE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"skill_id":"zapusk-otdela-prodazh-os"}' \
  "https://skills.comandos.ai/api/skills/install.sh" \
  | bash
```

## Что внутри

- `SKILL.md` - главная инструкция для агента.
- `AGENTS` template - правила работы внутри папки конкретной установки.
- `LAUNCH_ROADMAP` template - чеклист запуска простым языком.
- `LAUNCH_STATE` template - состояние запуска для агента.
- `PROJECT_NOTES` template - заметки по решениям, ограничениям и ручным действиям.
- Supabase-инструкция и SQL для схемы `sales_department`, включая deployment discovery, внешний connection gate для COMANDOS ОС, `knowledge_rag`, `products_live`, HNSW/GIN-индексы и функции гибридного поиска.
- Telegram-инструкция и готовые скрипты: поиск существующей Telethon-сессии, безопасное создание новой с `ru/ru-RU`, запуск живого диалога и приватный локальный отчет.
- amoCRM-инструкция: OAuth, callback/webhook, CRM setup prompt.
- Research/brief/field-plan инструкция: как из документов, RAG, сайта, конкурентов и аудитории собрать проверяемую гипотезу, подтвердить ее с владельцем, выбрать стратегию рекомендаций, список данных, живую цепочку квалификации и qualification gate: какие факты обязательны до консультации.
- Prompt skeletons: квалификатор и консультант с правилами нативного сбора данных, runtime-снимком заполненности полей, запретом ранней консультации, коротким менеджерским стилем по умолчанию и продажей решения только через найденную боль.
- CRM templates: snapshot amoCRM, field gap, карта правил и критериев переходов по воронке, setup-команда CRM-оператора, пример финального prompt-а CRM-оператора под реальный вход COMANDOS ОС (`crm_operation_input`, `tool_calls`, `crm_result`).
- Финальная проверка: Telegram smoke-test и CRM smoke-test.

## Как агент должен вести запуск

1. Создать `AGENTS.md`, `LAUNCH_ROADMAP.md`, `LAUNCH_STATE.json` и `PROJECT_NOTES.md`.
2. Остановиться после этапа 0 и не запускать Supabase, Telegram, базу знаний, prompts, amoCRM, smoke-test или deploy без отдельной команды.
3. Уточнить режим запуска.
4. Идти по шагам, не перескакивать.
5. После каждого шага обновлять roadmap/state/notes.
6. Не сохранять секреты в файлы.
7. В конце показать, что готово, что не готово и что надо проверить руками.

## Что крутого и полезного

- Агент не теряет контекст: есть живой чеклист и state.
- Человек получает один следующий шаг, а не пачку хаотичных инструкций.
- Supabase можно подключить двумя способами: агент сам применяет SQL или ведет человека через Supabase UI.
- Если Supabase найден на SSH/VPS, агент не считает этап готовым по внутреннему Docker-подключению: сначала нужна проверенная внешняя строка для COMANDOS ОС или подтвержденная общая сеть.
- База знаний для отдела продаж всегда пишется и проверяется в `sales_department`, чтобы не было путаницы со старой `public`-схемой.
- CRM-оператор не включается вслепую: сначала собирается snapshot amoCRM, потом владелец подтверждает критерии переходов по воронке и правила полей, потом финальный prompt собирается под реальные поля клиента и реальный контракт COMANDOS ОС.
- Prompts квалификатора и консультанта не пишутся "из головы": сначала агент исследует материалы, RAG, сайт, аудиторию, боли и конкурентов, показывает владельцу гипотезу, подтверждает модель продажи/стратегию рекомендаций, затем фиксирует brief и план данных.
- Переход в консультацию не решается на глаз: в `field_plan.md` фиксируется обязательный минимум фактов, а в prompt каждый раз передается, что уже собрано и что еще пустое.
- Квалификатор и консультант не стартуют с анкеты: сначала польза по сообщению клиента, потом один нативный вопрос про боль, путь заявки/процесса или последствия.
- Default-стиль не должен звучать как механическая анкета: коротко, живо, без "помогу понять, откуда у вас идут заявки".
- Setup-agent на этапе 0 создает локальный порядок проекта: `AGENTS.md`, `LAUNCH_ROADMAP.md`, `LAUNCH_STATE.json`, `PROJECT_NOTES.md`.
- Setup-agent сохраняет рабочие файлы следующих этапов: `audience_research.md`, `company_brief.md`, `field_plan.md`, `amocrm_snapshot.json`, `crm_field_gap.md`, `crm_mapping.md`, `crm_operator_prompt.md`.
- Старый n8n-сценарий не используется и не мешает новой ОС.
- Старый `telegram-testirovanie-bota` этому пакету не нужен: здесь нет n8n test workflow, а Telegram-тест запускается только через `scripts/telegram_session_doctor.py`, `scripts/login_telethon_session.py` и `scripts/telegram_os_smoke.py`.
