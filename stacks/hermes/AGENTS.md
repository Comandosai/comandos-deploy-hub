# Роль агента

Ты разворачиваешь COMANDOS Hermes на VPS из текущей папки `Hermes`.

Не создавай вложенную папку `Hermes`. Текущая директория уже является корнем установщика.

## Главная цель

Пользователь должен получить рабочий COMANDOS Hermes:

1. панель COMANDOS Workspace;
2. Hermes Agent gateway;
3. Telegram-бот, если пользователь заполнил Telegram-настройки;
4. проверка лицензии COMANDOS при входе в панель;
5. HTTPS-доступ;
6. сгенерированный 24-символьный пароль панели;
7. закреплённые версии без тихого автообновления;
8. уведомления о проверенных обновлениях через COMANDOS manifest.

## Перед развёртыванием

Сначала прочитай:

1. `comandos-hermes.env`
   - если пользователь заполнил `comandos-hermes.env.example`, а основной env пустой или не проходит проверку, используй example;
2. `comandos-hermes.lock`
3. `docs/INSTALLER_SPEC.md`
4. `docs/UPDATE_POLICY.md`

Потом проверь основной env:

```bash
bash scripts/check-config.sh comandos-hermes.env
```

Если основной env не прошёл, но пользователь заполнил `comandos-hermes.env.example`, проверь example:

```bash
bash scripts/check-config.sh comandos-hermes.env.example
```

Если не прошёл ни один файл, остановись и покажи пользователю только список незаполненных или неверных полей. Секреты не печатай.

## Правила установки

- Не ставь Hermes или Workspace из `latest`, `main` или плавающего архива без проверки `comandos-hermes.lock`.
- Публично открывай только итоговый адрес панели из установщика.
- Не поднимай дополнительные публичные веб-сервисы без явного запроса пользователя.
- На сервере Workspace должен лежать без `.git`; обновление разрешено только через `COMANDOS_UPDATE_MANIFEST_URL` и `comandos-update.sh`.
- Не запускай `hermes update`.
- Не добавляй cron/timer для автообновлений.
- Пароль панели генерируй сам, 24 символа.
- Telegram необязателен для первого запуска панели.
- Если пользователь заполнил Telegram, обязательны оба поля: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_USER_ID`.
- Если Telegram включён, `TELEGRAM_USER_ID` попадает в первый маршрут `Telegram ID -> default profile`.
- Если Telegram включён, Telegram-роутер должен запускаться через `comandos-telegram.service`; не возвращай старую Node.js-заглушку.
- Если `DOMAIN` заполнен, ставь HTTPS на домен.
- Если `DOMAIN` пустой, ставь HTTPS через `https://ROOT_IP.nip.io`.

## Что нельзя делать

- Нельзя стирать чужие файлы на сервере без явного подтверждения.
- Нельзя открывать наружу Hermes gateway.
- Нельзя оставлять панель на голом HTTP.
- Нельзя печатать API-ключи в лог.
- Нельзя коммитить или отправлять `comandos-hermes.env`.
- Нельзя включать тихое автообновление.
- Нельзя менять обновление на upstream Hermes без COMANDOS manifest.

## Критерий готовности

В конце развёртывания выведи:

```text
COMANDOS Hermes готов.

URL панели: ...
Пароль панели: ...
Лицензия: вводится пользователем при входе
Hermes gateway: active
Workspace service: active
Telegram bot: active или disabled
Версии зафиксированы: да
Автообновление: выключено
Уведомления об обновлениях: включены
```

Если что-то не прошло проверку, не пиши "готово". Покажи конкретную причину и команду для диагностики.

## Граница контекста

Контур этого проекта: `COMANDOS`.

Перед работой читай только карточку COMANDOS, карточку текущего продукта, ближайшие `README.md` и `AGENTS.md`. Очередь решений открывай только для COMANDOS и только если задача ждёт решения владельца или создаёт настоящий блокер.

Не читай, не передавай и не упоминай данные, карточки, блокеры или отчёты InLogic и Work. Исключение — только прямая команда владельца с явно названными контурами и минимально нужными данными.

Если создаётся новый самостоятельный проект или сервис, сначала создай или выбери его карточку под COMANDOS, затем зарегистрируй ближайший `AGENTS.md` и пройди канонический старт проекта.
