# Правила для агента

Этот файл про то, как агент должен работать с навыками в этом репозитории.

## Главный принцип

Пользователь не должен разбираться в внутренней структуре.
Агент сам:
- выбирает нужный навык;
- подтягивает зависимости;
- открывает правильный файл инструкций под нужного клиента (`codex`, `claude`, `gemini`).

## Что читать агенту

1. `registry/skills-index.json` — список навыков и зависимостей.
2. Папку выбранного навыка.
3. Файл инструкций под клиента:
   - `AGENTS.md` для Codex;
   - `CLAUDE.md` для Claude;
   - `GEMINI.md` для Gemini;
   - если файла нет, использовать `SKILL.md`.

## Как агент выбирает следующий файл

1. Если пользователь назвал клиента, использовать его файл инструкций.
2. Если не назвал, пробовать в порядке:
   - `AGENTS.md`
   - `CLAUDE.md`
   - `GEMINI.md`
   - `SKILL.md`
3. Если есть зависимости, сначала поставить их, потом основной навык.

## Как агент ставит навык

Рекомендуемая команда:

```bash
curl -sSL https://raw.githubusercontent.com/Comandosai/comandos-deploy-hub/main/tools/skills.sh | bash -s -- install <skill_id> --client <codex|claude|gemini>
```

Если клиент не указан, агент всё равно ставит навык и берёт `SKILL.md` как базовую инструкцию.

## Политика совместимости

- Не ломать старые пути.
- Не удалять существующие файлы инструкций.
- Новые навыки обязательно добавлять в `registry/skills-index.json`.

## Обязательный финал перед push

Если добавлен новый навык или изменён существующий, агент обязан перед push:

1. Обновить `registry/skills-index.json`:
   - добавить или обновить запись навыка;
   - проверить `id`, `path`, `depends_on`, `clients`.
2. Прогнать проверку:
   - `./tools/check.sh`
3. Если `./tools/check.sh` не проходит:
   - push запрещён;
   - сначала исправить реестр/структуру.

Главное правило:
- есть папка `skills/<skill_name>` → должна быть запись в `registry/skills-index.json`.
